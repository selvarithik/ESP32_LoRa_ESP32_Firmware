Default partition layout remains: NVS 0x9000+0x5000; OTA metadata 0xe000+0x2000; app0 0x10000+0x140000; app1 0x150000+0x140000; SPIFFS 0x290000+0x160000; coredump 0x3f0000+0x10000. Huge App was inspected (0x300000 app, no app1, 0xe0000 SPIFFS) and not selected because the completed build fits. It would not resolve heap or NVS capacity.

PlatformIO upload completed and verified hashes. Normal upload erased/replaced its bootloader, partition-table, OTA-metadata and application regions; no full-chip erase, factory reset, NVS/SPIFFS format or fuse write was performed. The second OTA slot/layout is preserved; an actual OTA cycle remains untested.

Two concurrent verified TLS sessions were exercised. Queue storage was changed to bounded, dynamically allocated owned frames to recover RAM. Representative stack free high-water readings were about 7.7 KB for the 12 KB loop stack and 4 KB for the 8 KB network stack. Whole-heap readings include non-8-bit memory and must not be interpreted as available TLS allocation space. Peak 8-bit heap margin is small; allocation failures reject work rather than accepting partial JSON. Worst-case simultaneous API/payload/candidate stress and extended memory soak remain pending.
