## Storage failure found and fixed

The original attempt failed with actual nvs_set_str NOT_ENOUGH_SPACE. Private backup metadata showed a 20,480-byte NVS partition with fragmented free entries and a 2,318-byte config_v1 string occupying 74 entries. No secret values were output during inspection. String replacement needed contiguous space; verified chunked blob persistence allows page-spanning storage.

ConfigManager now reads device/config_blob_v1 when present and otherwise migrates legacy device/config_v1. It writes the complete unchanged canonical JSON as an NVS blob, reads back exact bytes, and only then removes the legacy string. Write/verify failure retains the legacy record; invalid existing blobs fail closed for writes. Cleanup failure leaves both records with the verified blob authoritative. The physical Master successfully migrated and saved the new pins. Cold-boot read-back is pending owner power-cycle; interrupted-power hardware tests remain pending. NVS remains unencrypted unless separately provisioned; encrypted DPAPI backups do not imply on-chip encryption.

This proven storage incompatibility required contract 1.4.1, wire schema still 1. Both repository contract files are byte-identical, SHA-256 cdd19216fb270c93b3347aa894f0c90d7a40a1040d73da5c4d23da403a6aada5. No canonical fields, topics, broker profiles, payloads or security settings changed. Gateway change is the identical contract document only.
