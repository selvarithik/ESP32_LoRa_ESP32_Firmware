# Command protocol 1 — offline software extension 2

Packet envelope is the existing fifteen-field Message, protocol_version=1: message_id, source, destination, origin_id, final_destination_id, next_hop, type, ttl, timestamp, sequence_number, correlation_id, payload, payload_length, payload_crc32. payload is compact UTF-8 JSON, max2048 bytes; frame max4096. CRC32 covers payload bytes. No new MQTT topics or JSON packet schema.

COMMAND payload: command_id=message_id, command, arguments object. Source/target immutable identities, not display names. Timestamp is UTC seconds; expiry bounded by message_max_age_ms and Gateway command timeout. Master routes by destination; never broadcasts privileged operations. Validate permissions at HTTP/MQTT ingress and device source/assignment checks. Sensitive credentials cannot be command arguments.

ACK payload: command_id, status RECEIVED; correlation_id matches command ID. This acknowledges receipt only. RESPONSE payload: command_id, status SUCCESS or FAILED, data object with actual result/error; correlation_id matches. Gateway lifecycle QUEUED -> SENT -> ACKNOWLEDGED -> COMPLETED/FAILED/TIMEOUT. Legacy DB ACK_RECEIVED maps to ACKNOWLEDGED; intermediate historical states remain supported. Lost ACK may be followed by an execution RESPONSE. Retries preserve command IDs and request bytes; mismatched content under an ID fails. Volatile normal-command dedup is bounded to32; restart additionally has a durable NVS marker/result. General exactly-once execution across power loss is not promised; config writes are idempotent. Command events remain in existing SQLite history.

RESTART takes no arguments. It persists a marker before restarting, sends receipt ACK, and reports execution after next boot (reset_reason). No pre-reboot SUCCESS response. SET_SLEEP_SCHEDULE takes the five sleep fields documented in CONFIG_CONTRACT (wifi_dns2 is not a schedule field). CONFIG_UPDATE supports documented non-secret config only; network/identity-changing operations report reboot requirements. WIFI_SCAN starts/reads asynchronous scan; GET_NETWORK returns actual IP, DNS and diagnostic state. RADIO_TEST is unsupported when driver unavailable; no fabricated ACK/RSSI/SNR.

Software simulator is explicitly SIMULATED and runs against disposable database/listener; never enroll demo devices into the owner's database. Packet loss/retries, duplicate execution, reboot and timeout tests must not be presented as hardware results.

GET_CONFIG command returns a bounded config_scope=RUNTIME snapshot (identity, revision, names, intervals, local-IP/public static network, sensor and sleep fields). Full public device settings remain available at the existing authenticated local /api/config endpoint. Unknown/unsupported hardware fields are not fabricated.
